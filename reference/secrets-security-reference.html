YAML anatomy & selectors 00

apiVersion: apps/v1   # v1 = core; apps/v1, networking.k8s.io/v1
kind: Deployment
metadata:             # name, namespace, labels, annotations
  name: demo-app
  namespace: demo
  labels: {app: demo-app}
spec:                 # desired state (ConfigMap/Secret: data)
  selector:
    matchLabels: {app: demo-app}   # immutable!
  template:
    metadata:
      labels: {app: demo-app}      # must match selector
# status: current state, written by Kubernetes only
---                   # next object in same file

YAML: spaces only, no tabs; key: value = map, - x = list; quote "3", "yes"; | = multi-line block. Selector = standing label query: Pods come and go, the query stays. Comma = AND, no OR.

ObjectSelector picks
Deployment / RSPods it counts (matchLabels, matchExpressions)
ServicePods that get traffic → EndpointSlice
NetworkPolicyPods a rule applies to (podSelector)
  • kubectl explain deployment.spec.selector field docs from the cluster
  • kubectl get pods -n demo --show-labels · -l app=demo-app see / filter labels
  • kubectl get endpointslices -n demo Pod IPs behind a Service
  • kubectl label pod NAME app=debug --overwrite pull Pod out of rotation; controller replaces it

Selector keys: stable app.kubernetes.io/name (+ instance); version only as extra label. Annotations for non-identifying notes. apply is per object, not all-or-nothing.

ConfigMap vs Secret 01

Leaking it would hurt → Secret; everything else → ConfigMap. Both max 1 MiB. Secret data is base64: an encoding, not encryption. Secrets: sent only to nodes that need them, mounted on tmpfs. Stored unencrypted in etcd by default (EKS 1.28+: KMS envelope encryption of all API data).

Consumed asRunning Pod sees change?
env varNo. Set at container start; restart.
volumeYes, eventually (kubelet sync + cache; ~20 s in demo). App must re-read.
subPath fileNo, never.
  • kubectl create secret generic db-credentials -n demo --from-literal=password='S3cr3t!' Opaque; literal lands in shell history
  • kubectl get secret db-credentials -n demo -o jsonpath='{.data.password}' | base64 -d decode: no key needed
  • kubectl describe secret NAME polite view: sizes only
  • kubectl patch secret NAME --type merge -p '{"stringData":{"password":"N3wP4ss!"}}' plain text in, API encodes
  • kubectl create secret docker-registry regcred --docker-server=… --docker-username=… --docker-password=… → imagePullSecrets
  • kubectl create secret tls demo-tls --cert=tls.crt --key=tls.key
  • kubectl rollout restart deployment/demo-app -n demo pick up env / subPath changes

Types: Opaque (default), kubernetes.io/dockerconfigjson (key .dockerconfigjson; jsonpath \.), kubernetes.io/tls (tls.crt, tls.key). immutable: true: data never changes, no undo; use versioned names (app-config-v2).

# container: key as env, objects as dirs
env:
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:   # or configMapKeyRef
        name: db-credentials
        key: password
volumeMounts:
  - name: config
    mountPath: /etc/config
    readOnly: true
  - name: secret
    mountPath: /etc/secret
    readOnly: true
# pod spec
volumes:
  - name: config
    configMap:
      name: app-config
  - name: secret
    secret:
      secretName: db-credentials

RBAC 02

Authn "who are you?" → 401. Authz (RBAC) "may you?" → 403 Forbidden. No User objects. Deny by default; permissions only add up, no deny rules.

Binding→ roleGrants
RoleBindingRolein its namespace
RoleBindingClusterRoleonly in the binding's namespace
ClusterRoleBindingClusterRoleevery namespace + cluster-scoped

Rule = verbs × resources × apiGroups (core = "", Deployments = "apps"). SA username system:serviceaccount:<ns>:<name>. roleRef is immutable: delete + recreate. Built-in view cannot read Secrets; edit can.

apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: configmap-reader
  namespace: demo
rules:
  - apiGroups: [""]
    resources: ["configmaps"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: config-reader-configmap-reader
  namespace: demo
subjects:
  - kind: ServiceAccount
    name: config-reader
    namespace: demo
roleRef:         # immutable
  apiGroup: rbac.authorization.k8s.io
  kind: Role       # or ClusterRole
  name: configmap-reader
  • kubectl auth can-i list configmaps -n demo --as=system:serviceaccount:demo:config-reader yes/no; exit 0/1
  • kubectl auth can-i --list -n demo --as=… everything it may do
  • kubectl get rolebinding -n demo -o wide role + subjects
  • kubectl create role NAME -n demo --verb=get,list --resource=configmaps --dry-run=client -o yaml skeleton
  • aws eks create-access-entry --cluster-name … --principal-arn … --kubernetes-groups demo-viewers IAM human → group; bind with kind: Group

Secrets Manager + ESO 03

Git holds the reference; AWS Secrets Manager holds the value; ESO writes a normal Secret; the Pod reads it as in 01. Use external-secrets.io/v1 (v1beta1 not served).

ObjectAnswers
SecretStorehow to reach the provider; one namespace
ClusterSecretStoresame, every namespace may use it: limit with spec.conditions
ExternalSecretwhat to fetch, how often, which Secret to write
target Secretplain v1/Secret, owned by the ExternalSecret
 
apiVersion: external-secrets.io/v1
kind: SecretStore
metadata:
  name: aws-secrets-manager
  namespace: demo
spec:
  provider:
    aws:          # no auth: Pod Identity
      service: SecretsManager
      region: eu-central-1
---
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: app-db
  namespace: demo
spec:
  refreshInterval: 1m  # 1h common
  secretStoreRef:
    kind: SecretStore
    name: aws-secrets-manager
  target:
    name: app-db-credentials
    creationPolicy: Owner
  data:
    - secretKey: password  # key in k8s Secret
      remoteRef:
        key: codecool/demo/app-db  # AWS name
        property: password         # JSON key
  • aws secretsmanager create-secret --name codecool/demo/app-db --secret-string file://app-db-v1.json from file, not history
  • aws secretsmanager put-secret-value --secret-id codecool/demo/app-db --secret-string file://… new version, AWSCURRENT
  • kubectl get secretstore,externalsecret -n demo want Valid / SecretSynced True
  • kubectl describe externalsecret app-db -n demo → then describe secretstore Events, bottom-up
  • kubectl annotate externalsecret app-db -n demo force-sync=$(date +%s) --overwrite sync now
  • aws eks list-pod-identity-associations --cluster-name codecool-demo SA → role mapping
  • kubectl get pod -n external-secrets -l app.kubernetes.io/name=external-secrets -o yaml | grep -A1 AWS_CONTAINER Pod Identity injected?

Manual edits to the target Secret are overwritten: AWS is the source of truth. The Secret is still base64 inside; RBAC still decides who reads it.

Pod Identity vs IRSA vs static keys 03

OptionHow · lifetime · setup · runs on
EKS Pod Identity (AWS's choice on EKS)association SA → IAM role; node agent hands out temporary, auto-rotated creds. Agent add-on, no OIDC provider. Trust pods.eks.amazonaws.com: same role works in a new cluster. Session tags (cluster, ns, SA). EKS, Linux EC2 only (no Fargate).
IRSA (fine; needed off EKS)SA annotated with role ARN; projected OIDC token → AssumeRoleWithWebIdentity. Temporary, auto-rotated. One OIDC provider per cluster (limit 100); trust names each issuer. No session tags. EKS, EKS Anywhere, ROSA, self-managed.
Static access keys (avoid)IAM user key in a k8s Secret. Valid forever, until a human rotates it. Works anywhere: the very problem we are solving.

Injected only at Pod start: association added later → rollout restart. IAM: only GetSecretValue + DescribeSecret on codecool/* (ARNs end in a 6-char suffix, so *).

NetworkPolicy 04

Default: every Pod reaches every Pod. Needs an enforcing CNI, else stored but ignored, no warning (EKS: VPC CNI with enableNetworkPolicy, aws-node 2/2; elsewhere Calico, Cilium). L3/L4 only. Allow-lists only: union of all policies selecting a Pod. A connection needs source egress AND destination ingress.

Peers: podSelector (same ns) · namespaceSelector (all Pods there; kubernetes.io/metadata.name) · both in one item = AND · ipBlock (cluster-external CIDRs).

# 1 · deny all, both ways, whole namespace
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: demo
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
---
# 2 · DNS for everyone (forget it = outage)
kind: NetworkPolicy
metadata:
  name: allow-dns-egress
spec:
  podSelector: {}
  policyTypes: [Egress]
  egress:
    - to:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name:
                kube-system
          podSelector:  # no "-": AND
            matchLabels:
              k8s-app: kube-dns
      ports:
        - {protocol: UDP, port: 53}
        - {protocol: TCP, port: 53}
---
# 3 · backend ingress from frontend :8080
kind: NetworkPolicy
metadata:
  name: backend-allow-from-frontend
spec:
  podSelector:
    matchLabels: {app: backend}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels: {app: frontend}
      ports:
        - {protocol: TCP, port: 8080}
# 4 · + frontend egress → backend :8080

AND vs OR: an extra - before podSelector makes two peers (OR): any Pod in kube-system. kubectl describe networkpolicy: one To: = AND, two = OR.

  • kubectl get pods -n kube-system -l k8s-app=aws-node 2/2 = policy agent on
  • kubectl -n demo exec deploy/frontend -- curl -sS -m 3 -o /dev/null -w '%{http_code}\n' http://backend:8080 always -m: drops, not refusals
  • kubectl -n demo run tester --rm -i --restart=Never --image=curlimages/curl:8.11.1 -- sh -c "sleep 5; curl -sS -m 3 http://backend:8080" ephemeral test; add --labels=app=frontend
  • kubectl get networkpolicy -n demo · describe networkpolicy NAME

DaemonSets 05

One Pod per eligible node; Pods follow nodes (added on join, removed on leave). No replicas. Selector required, immutable, must match template labels. EKS: aws-node, eks-pod-identity-agent, kube-proxy.

kind: DaemonSet
spec:
  updateStrategy:
    type: RollingUpdate      # default; or OnDelete
    rollingUpdate: {maxUnavailable: 1}
  template:
    spec:
      nodeSelector: {role: logging}   # only these nodes
      tolerations:                    # allow tainted nodes
      - key: dedicated               # our demo taint
        operator: Exists
        effect: NoSchedule

Auto-tolerations: not-ready, unreachable, disk/memory/pid-pressure, unschedulable. Not your own taints (e.g. dedicated) or control-plane.

  • kubectl get ds -A DESIRED = eligible nodes
  • kubectl get pods -n demo -o wide NODE column: one per node
  • kubectl describe node NAME | grep Taints
  • kubectl rollout status|history|undo ds/NAME -n demo
  • kubectl label node NAME role=logging · role- Pod appears / goes

Best-practices checklist

  • Selectors never overlap between controllers 00
  • Small, stable selector (app.kubernetes.io/name); version outside it 00
  • Secrets in a Secret, never in a ConfigMap or the image 01
  • No secret values in Git, not even for dev 01 03
  • Encryption at rest on (EKS default); guard your own KMS key 01
  • Never log a Secret; mount it only where needed 01
  • Versioned immutable ConfigMaps for config changes 01
  • Least privilege; RoleBinding over ClusterRoleBinding 02
  • No cluster-admin, no "*" wildcards 02
  • get/list/watch on Secrets = read all; resourceNames for one 01 02
  • One ServiceAccount per workload, never default 02
  • automountServiceAccountToken: false unless the app calls the API 02
  • Remember: create Pods = use any SA in that namespace 02
  • Pod Identity, not static keys; IAM scoped to a name prefix 03
  • Namespaced SecretStore per team; ClusterSecretStore with conditions 03
  • Restart after rotation if the app uses env, subPath or caches 01 03
  • Default deny + DNS allow per namespace, then one policy per flow 04
  • Labels are a security control: few, stable, reviewed 04
  • Test must-work and must-fail paths with a curl Pod and a timeout 04
  • DaemonSets: requests/limits, high priorityClassName for critical agents 05
  • Node agents are high-risk (hostNetwork/hostPath): trusted image, own SA, least RBAC 05

Symptom → where to look

  • `selector` does not match template `labels` → template labels must contain the selector 00
  • spec.selector … field is immutable → delete + recreate the Deployment 00
  • Service up, no traffic → describe svc: empty Endpoints = selector typo; compare --show-labels 00
  • App still has old value → env var or subPath? Restart. Volume: wait the kubelet sync; does the app re-read? 01 03
  • field is immutable → immutable: true ConfigMap/Secret, or a binding's roleRef: delete + recreate 01 02
  • Too long: may not be more than 1048576 bytes → 1 MiB limit; use a volume or object storage 01
  • Error from server (Forbidden) → read user, verb, resource, API group, namespace: that is the missing rule. auth can-i --list --as=… 02
  • Pod: localhost:8080 was refused → no token mounted: automountServiceAccountToken 02
  • SecretSyncedError → describe externalsecret, then describe secretstore 03
  • no EC2 IMDS role found → no Pod Identity: check association + AWS_CONTAINER_* env; restart ESO 03
  • AccessDeniedException … GetSecretValue → IAM policy misses this name (outside codecool/) 03
  • Secret does not exist → typo in remoteRef.key or wrong region 03
  • key … does not exist in secret → remoteRef.property typo (case-sensitive) 03
  • curl: (28) Resolving timed out → DNS egress blocked: allow kube-dns UDP+TCP 53 04
  • curl: (28) Connection timed out → port blocked: check egress on source AND ingress on target, and labels (get pods --show-labels) 04
  • Policy applied, nothing blocked → no enforcing CNI (aws-node 1/1?); on EKS a bare Pod tested too early 04
  • DaemonSet DESIRED < nodes → taint without toleration (describe node), or nodeSelector label missing 05
  • DaemonSet Pod vanished from a node → node label changed and no longer matches nodeSelector 05
