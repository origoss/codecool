## Verified, and how

### Versions (checked live)
- Registry API (`registry.terraform.io/v1/modules/...`): vpc **6.7.3** (2026-09-18), eks **21.29.0** (2026-10-07).
- `hashicorp/aws`: 6.70.0 is on registry.terraform.io but **not yet on registry.opentofu.org**, where the newest is 6.69.1. Init failed with `~> 6.70`, so the pin is `~> 6.69`.
- ESO chart: `helm search repo external-secrets/external-secrets -l` returned latest **2.13.0** (app v2.13.0) from `https://charts.external-secrets.io`.
- ESO API version: rendered the chart CRDs with `helm template --include-crds`. `ExternalSecret`, `SecretStore` and `ClusterSecretStore` have `v1` served + storage, while `v1beta1` is `deprecated: true, served: false`. Confirmed with `kubectl api-resources` after install.
- EKS standard support lists Kubernetes 1.37 as newest (AWS docs).

### Docs (fetched, not from memory)
- ESO aws-access: with Pod Identity the SecretStore needs no `auth`, and `serviceAccountRef` must not be combined with Pod Identity.
- AWS Pod Identity: trust policy, session tag keys, injected env vars and agent address `169.254.170.23`, no Fargate, Pod Identity vs IRSA comparison table and AWS recommendation.
- VPC CNI network policy: `{"enableNetworkPolicy": "true"}`.
- Secrets Manager: create-secret, put-secret-value and list-pod-identity-associations CLI example outputs; pricing.
- EKS pricing.
- Kubernetes: Secret volumes update eventually, `subPath` mounts do not, ConfigMap env vars are not updated (anchors checked).
- GitHub: rotate leaked secrets first.
- ESO FAQ: force-sync annotation.

### Kubernetes / ESO behaviour (own kind cluster, with the fake provider standing in for AWS)
Setup:
- Separate cluster `eso-lesson` created with `go run sigs.k8s.io/kind@v0.33.0`, image `kindest/node:v1.37.0`, and its own kubeconfig in the session scratchpad.
- Other agents' clusters (`kind`, `rbac-lesson`, `netpol-lesson`, `iac-vs-iad`) were not touched.
- Installed `helm install external-secrets external-secrets/external-secrets -n external-secrets --create-namespace --version 2.13.0 --wait`. Pods and the ServiceAccount `external-secrets` were confirmed, as were the pod labels (`app.kubernetes.io/name=external-secrets`).

Captured as real output:
- The **AWS** SecretStore without credentials gave `InvalidProviderConfig` with the message `failed to refresh cached credentials, no EC2 IMDS role found, ...`.
- The ExternalSecret then showed `SecretSyncedError` with the event `SecretStore "aws-secrets-manager" is not ready`. Both are used verbatim in the troubleshooting section.
- After switching the store to the fake provider:
  - SecretStore showed `Valid` / `ReadWrite` / `True`.
  - The ExternalSecret reached `SecretSynced` after the `force-sync` annotation (it was otherwise in back-off).
  - The target Secret is `Opaque` with 2 keys, owned by `ExternalSecret/app-db`.
  - The `kubectl get externalsecret` column layout matches.
- Rotation test with refreshInterval 1m:
  - The Secret updated about 45–50s after the value change.
  - The mounted file updated about 20s later.
  - The env var never changed.
  - The Pod log lines in the lesson are from this run.
- Manual `kubectl patch` of the target Secret was reverted by ESO within 3s.
- `kubectl delete externalsecret` deleted the target Secret (`creationPolicy: Owner`).
- A wrong remote key gave the event `... err: Secret does not exist`.
- `99-clustersecretstore.yaml` passed `kubectl apply --dry-run=server`.

From source code:
- ESO v2.13.0 `providers/v1/aws/secretsmanager/secretsmanager.go`: `ResourceNotFoundException` maps to `NoSecretErr` ("Secret does not exist"), and a missing property gives `key %s does not exist in secret %s`.

## Open issues / notes for the instructor
- The ESO Helm release **must** be named `external-secrets` in namespace `external-secrets` (SA name = association). This is in the README.
- If ESO is installed before the association exists, run `kubectl rollout restart deployment external-secrets -n external-secrets`. This is in the README and the lesson.
- The trust policy requires the session tags `eks-cluster-name`, `kubernetes-namespace` and `kubernetes-service-account`. If someone disables session tags on the association, AssumeRole fails. The conditions can be removed if that is a concern.
- The lesson assumes the `demo` namespace exists (NOTES.md). `examples/external-secrets-aws/00-namespace.yaml` is provided but not referenced in a demo step.
- Link `../reference/secrets-security-reference.html` points to a sheet that does not exist yet. Prev/next links (0002 / 0004) depend on other agents' files.
- `.parts/` resources and glossary still need merging into `RESOURCES.md` / `GLOSSARY.md` by the instructor.
- The EKS module adds an `intra` subnet set for the control plane ENIs. This is harmless, but `tofu destroy` may need a retry if ENIs linger.
- State is local (`infra/terraform.tfstate` after apply). Use a remote backend if more than one person applies.
